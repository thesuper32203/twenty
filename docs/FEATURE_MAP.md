# Feature map

Use the path and symbol in each row as a starting point; inspect current implementation and tests before editing. Generic metadata-driven record routes serve many CRM objects, so there is not one controller per object. See [ARCHITECTURE.md](ARCHITECTURE.md) for the shared request path and [DATABASE_MAP.md](DATABASE_MAP.md) for persistence.

| Feature | UI and implementation entry points | Models, API and dependencies |
| --- | --- | --- |
| Records, lists and views | [`RecordIndexPage`](../packages/twenty-front/src/pages/object-record/RecordIndexPage.tsx), [`RecordShowPage`](../packages/twenty-front/src/pages/object-record/RecordShowPage.tsx); [`WorkspaceGraphQLSchemaFactory`](../packages/twenty-server/src/engine/api/graphql/workspace-schema-builder/workspace-graphql-schema.factory.ts), [`WorkspaceResolverBuilderService`](../packages/twenty-server/src/engine/api/graphql/workspace-resolver-builder/workspace-resolver-builder.service.ts), [`WorkspaceRepository`](../packages/twenty-server/src/engine/twenty-orm/repository/workspace-repository.ts) | Metadata-generated GraphQL operations and [`RestApiCoreController`](../packages/twenty-server/src/engine/api/rest/core/controllers/rest-api-core.controller.ts): `GET`, `POST`, `PATCH`, `PUT`, `DELETE`, batch, groupBy, duplicates, restore, merge beneath `ApiPath.Rest`. [`ObjectMetadataEntity`](../packages/twenty-server/src/engine/metadata-modules/object-metadata/object-metadata.entity.ts), [`FieldMetadataEntity`](../packages/twenty-server/src/engine/metadata-modules/field-metadata/field-metadata.entity.ts), [`ViewEntity`](../packages/twenty-server/src/engine/metadata-modules/view/entities/view.entity.ts). Depends on auth, metadata and TwentyORM. |
| People and companies | Generic record pages; [`PeopleTablePagination`](../packages/twenty-front/src/modules/object-record/record-index/components/PeopleTablePagination.tsx) and [`useTriggerInitialRecordTableDataLoad`](../packages/twenty-front/src/modules/object-record/record-table/virtualization/hooks/useTriggerInitialRecordTableDataLoad.ts) paginate ungrouped People tables in 20, 50 or 100 row requests; [`PersonWorkspaceEntity`](../packages/twenty-server/src/modules/person/standard-objects/person.workspace-entity.ts), [`CompanyWorkspaceEntity`](../packages/twenty-server/src/modules/company/standard-objects/company.workspace-entity.ts); [`CreateCompanyAndContactJob`](../packages/twenty-server/src/modules/contact-creation-manager/jobs/create-company-and-contact.job.ts) | Generic record GraphQL/REST. Person has a wholesale `propertyAddress` composite field (street, city, state, postcode); the People creation form shows name, phone number, email and property address. [`ConfigureWholesalePersonLayoutsCommand`](../packages/twenty-server/src/database/commands/upgrade-version-command/2-50/2-50-workspace-command-1792677914642-configure-wholesale-person-layouts.command.ts) updates saved forms and legacy custom All People views in existing workspaces. Person `companyId` links to company; both connect to activities, messages, tasks and notes. Connected account sync can create contacts. |
| Opportunities and properties | Generic record pages; [`OpportunityWorkspaceEntity`](../packages/twenty-server/src/modules/opportunity/standard-objects/opportunity.workspace-entity.ts), [`PropertyWorkspaceEntity`](../packages/twenty-server/src/modules/property/standard-objects/property.workspace-entity.ts), [`PersonPropertyWorkspaceEntity`](../packages/twenty-server/src/modules/property/standard-objects/person-property.workspace-entity.ts); [`OpportunityContactDetails`](../packages/twenty-front/src/modules/object-record/record-show/components/OpportunityContactDetails.tsx) | Generic record GraphQL/REST. Opportunity links its seller through `pointOfContactId` and its subject Property through `propertyId`; Property and Person connect through owner-role PersonProperty records. The Opportunity record page reads current contact details from Person. The configurable default Opportunity stages follow the wholesale workflow. The `byStage` board shows seller and property details, phone, next task, MAO and offer; task and note actions attach to the deal. Assignment fee sets projected profit, and stage changes appear as separate record-update timeline events, including rapid consecutive moves. |
| Homeowner CSV import and contact groups | [`HomeownerImportsPage`](../packages/twenty-front/src/pages/imports/HomeownerImportsPage.tsx) at `/imports`, linked from the Contacts & Data sidebar section; [`HomeownerImportLauncher`](../packages/twenty-front/src/modules/object-record/spreadsheet-import/components/HomeownerImportLauncher.tsx); [`HomeownerImportResolver`](../packages/twenty-server/src/modules/wholesale-import/resolvers/homeowner-import.resolver.ts) and [`HomeownerImportService`](../packages/twenty-server/src/modules/wholesale-import/services/homeowner-import.service.ts) | The wizard accepts up to 100,000 rows and commits 500-row chunks with retry progress under one ImportBatch. `homeownerImportHistory` reads the newest 50 batches and aggregates distinct resolved phone counts in the database. `previewHomeownerImport` and `commitHomeownerImport` coordinate Person, Property, PersonProperty, and optional Opportunity writes. [`ImportBatchWorkspaceEntity`](../packages/twenty-server/src/modules/homeowner-import/standard-objects/import-batch.workspace-entity.ts) and [`ImportRowResultWorkspaceEntity`](../packages/twenty-server/src/modules/homeowner-import/standard-objects/import-row-result.workspace-entity.ts) record batch and row outcomes. A named MessageList/MessageListMember group includes resolved People even when duplicate updates are skipped; generic List pages expose the group. Import membership alone does not establish SMS consent. |
| Tasks, notes, activities | Record pages and `twenty-front/src/modules/activities`; [`TaskWorkspaceEntity`](../packages/twenty-server/src/modules/task/standard-objects/task.workspace-entity.ts), [`NoteWorkspaceEntity`](../packages/twenty-server/src/modules/note/standard-objects/note.workspace-entity.ts), task/note target entities | Generic record GraphQL/REST. Target relations attach activities to people, companies and opportunities; task assignee links to workspace member. |
| Workflows | [`WorkflowCoreShowPage`](../packages/twenty-front/src/pages/object-core/WorkflowCoreShowPage.tsx); [`WorkflowRunnerWorkspaceService`](../packages/twenty-server/src/modules/workflow/workflow-runner/workspace-services/workflow-runner.workspace-service.ts), [`WorkflowExecutorWorkspaceService`](../packages/twenty-server/src/modules/workflow/workflow-executor/workspace-services/workflow-executor.workspace-service.ts), [`WorkflowRunEnqueueWorkspaceService`](../packages/twenty-server/src/modules/workflow/workflow-runner/workflow-run-queue/workspace-services/workflow-run-enqueue.workspace-service.ts) | [`WorkflowWorkspaceEntity`](../packages/twenty-server/src/modules/workflow/common/standard-objects/workflow.workspace-entity.ts), version, run and trigger entities. Generic record API plus workflow-specific services/jobs. Depends on queue, records, triggers, logic functions and optionally agents. Read [`WORKFLOW_CORE_EXECUTION.md`](../packages/twenty-server/docs/WORKFLOW_CORE_EXECUTION.md). |
| AI agents and chat | [`AiChatPage`](../packages/twenty-front/src/pages/ai-chat/AiChatPage.tsx); [`AgentChatResolver`](../packages/twenty-server/src/engine/metadata-modules/ai/ai-chat/resolvers/agent-chat.resolver.ts) (`chatThread`, `chatMessages`, `createChatThread`, `sendChatMessage`); [`AgentRunnerService`](../packages/twenty-server/src/engine/metadata-modules/ai/ai-agent-execution/services/agent-runner.service.ts) | [`AgentEntity`](../packages/twenty-server/src/engine/metadata-modules/ai/ai-agent/entities/agent.entity.ts), chat thread/message/turn workspace entities under [`ai-history/standard-objects`](../packages/twenty-server/src/engine/metadata-modules/ai/ai-history/standard-objects/). Depends on queue, model providers, tool registry, permissions and persisted history. See [AGENT_SYSTEM.md](AGENT_SYSTEM.md). |
| Messaging and calendar | [`modules/messaging`](../packages/twenty-server/src/modules/messaging/), [`modules/calendar`](../packages/twenty-server/src/modules/calendar/); message and calendar import jobs under each module | [`MessageWorkspaceEntity`](../packages/twenty-server/src/modules/messaging/common/standard-objects/message.workspace-entity.ts), [`CalendarEventWorkspaceEntity`](../packages/twenty-server/src/modules/calendar/common/standard-objects/calendar-event.workspace-entity.ts). Sync depends on connected accounts, providers, jobs and target/participant matching. Provider behavior is configuration-dependent. |
| Email campaigns | [`modules/emailing`](../packages/twenty-server/src/modules/emailing/), [`SendCampaignEmailJob`](../packages/twenty-server/src/modules/emailing/jobs/send-campaign-email.job.ts), [`UnsubscribeController`](../packages/twenty-server/src/modules/emailing/controllers/unsubscribe.controller.ts), [`CampaignTrackingController`](../packages/twenty-server/src/modules/emailing/controllers/campaign-tracking.controller.ts) | Message campaign/list/member, campaign delivery and suppression workspace entities under [`standard-objects`](../packages/twenty-server/src/modules/emailing/standard-objects/). Feature-specific GraphQL resolvers under `emailing/resolvers`; HTTP unsubscribe and tracking routes under `ApiPath.Emailing`. Depends on messaging/email transport and queue. |
| Extensions and integrations | [`twenty-sdk`](../packages/twenty-sdk/), [`twenty-cli`](../packages/twenty-cli/), [`twenty-apps`](../packages/twenty-apps/); server [`application`](../packages/twenty-server/src/engine/core-modules/application/) and [`logic-function`](../packages/twenty-server/src/engine/core-modules/logic-function/) modules | App metadata/logic functions, REST/GraphQL/MCP, webhooks, Zapier. Start at the relevant module; available routes and providers vary by installation. |

No distinct standard `LeadWorkspaceEntity` was found in the existing [source audit](CODEBASE_AUDIT.md); a lead can be modeled with existing or custom objects, but specific workspace configuration is unknown. For API work, use the actual controller/resolver decorator and generated schema as the endpoint authority.
