# Database map

Twenty uses PostgreSQL TypeORM core entities and metadata-driven TwentyORM workspace records. There is no Prisma schema in this checkout. This is a source map; inspect a migrated database for actual indexes, constraints and command state. See [UPGRADE_COMMANDS.md](../packages/twenty-server/docs/UPGRADE_COMMANDS.md) for authoritative upgrade rules.

## Core schema and metadata

[`core.datasource.ts`](../packages/twenty-server/src/database/typeorm/core/core.datasource.ts) sets PostgreSQL schema `core`, `synchronize: false`, and `migrationsRun: false`. [`WorkspaceEntity`](../packages/twenty-server/src/engine/core-modules/workspace/workspace.entity.ts) owns workspace-scoped metadata relations. [`ObjectMetadataEntity`](../packages/twenty-server/src/engine/metadata-modules/object-metadata/object-metadata.entity.ts) describes objects and relates to fields, indexes and views; singular/plural names have workspace-scoped unique decorators. [`FieldMetadataEntity`](../packages/twenty-server/src/engine/metadata-modules/field-metadata/field-metadata.entity.ts) relates to its object, has a unique `(name, objectMetadataId, workspaceId)` decorator, and a check requiring `morphId` for morph relations. [`ViewEntity`](../packages/twenty-server/src/engine/metadata-modules/view/entities/view.entity.ts) relates to object metadata and view fields/filters/sorts/groups. [`AgentEntity`](../packages/twenty-server/src/engine/metadata-modules/ai/ai-agent/entities/agent.entity.ts) is a core metadata entity with a workspace-scoped name index filtered by deletion state. Inspect decorators and generated SQL for the exact constraint behavior.

## Workspace record schemas

[`WorkspaceDataSourceService`](../packages/twenty-server/src/engine/twenty-orm/datasource/workspace-data-source.service.ts) obtains workspace connections (including an optional replica); [`WorkspaceRepository`](../packages/twenty-server/src/engine/twenty-orm/repository/workspace-repository.ts) and [`permissions.utils.ts`](../packages/twenty-server/src/engine/twenty-orm/repository/permissions.utils.ts) are the main data-access and permission navigation points. Standard typed objects describe fields and relations; workspace metadata and migrations determine physical schema.

| Record family | Representative model and important relationships |
| --- | --- |
| CRM | [`PersonWorkspaceEntity`](../packages/twenty-server/src/modules/person/standard-objects/person.workspace-entity.ts): `propertyAddress` (address composite), `companyId`, opportunity contacts, property owner links, task/note/message/calendar targets. [`PropertyWorkspaceEntity`](../packages/twenty-server/src/modules/property/standard-objects/property.workspace-entity.ts): address, normalized address key, owner links and opportunities. [`PersonPropertyWorkspaceEntity`](../packages/twenty-server/src/modules/property/standard-objects/person-property.workspace-entity.ts): Person–Property role relation. [`OpportunityWorkspaceEntity`](../packages/twenty-server/src/modules/opportunity/standard-objects/opportunity.workspace-entity.ts): `companyId`, `pointOfContactId`, nullable `propertyId`, `ownerId`, stage/amount/close date. Opportunities display linked Person contact details without duplicating them. |
| Homeowner intake | [`ImportBatchWorkspaceEntity`](../packages/twenty-server/src/modules/homeowner-import/standard-objects/import-batch.workspace-entity.ts) links to a named MessageList and stores filename, idempotency checksum, server payload digest, options, status and row counts. [`ImportRowResultWorkspaceEntity`](../packages/twenty-server/src/modules/homeowner-import/standard-objects/import-row-result.workspace-entity.ts) links to its batch and stores row number, outcome/reason and Person/Property/Opportunity identifiers. Existing [`MessageListWorkspaceEntity`](../packages/twenty-server/src/modules/emailing/standard-objects/message-list.workspace-entity.ts) and [`MessageListMemberWorkspaceEntity`](../packages/twenty-server/src/modules/emailing/standard-objects/message-list-member.workspace-entity.ts) hold reusable upload-group membership. |

The Person `propertyAddress` metadata expands into nullable columns in each workspace's `person` table (including street, city, state, and postcode). New workspaces receive them during standard application synchronization. Existing workspaces receive them through [`AddPersonPropertyAddressCommand`](../packages/twenty-server/src/database/commands/upgrade-version-command/2-50/2-50-workspace-command-1792446804535-add-person-property-address.command.ts), which uses the workspace migration runner to create field metadata, physical columns, and People view columns, then hide the old standard People list columns.

[`ConfigureWholesalePersonLayoutsCommand`](../packages/twenty-server/src/database/commands/upgrade-version-command/2-50/2-50-workspace-command-1792677914642-configure-wholesale-person-layouts.command.ts) updates existing Person creation form widgets, labels the single-value phone and email fields, and aligns legacy custom All People views with the wholesale columns. It hides old form and list fields without deleting contact data.

[`AddWholesaleImportObjectsCommand`](../packages/twenty-server/src/database/commands/upgrade-version-command/2-50/2-50-workspace-command-1792682985480-add-wholesale-import-objects.command.ts) adds the Property, PersonProperty and import-history standard metadata, physical tables, Opportunity–Property relation and views to existing workspaces. [`AddImportMappedColumnCountCommand`](../packages/twenty-server/src/database/commands/upgrade-version-command/2-50/2-50-workspace-command-1792690634489-add-import-mapped-column-count.command.ts) adds the saved mapped-column count to existing import batches. New workspaces receive them from standard application synchronization. The batch checksum and `(batch, row number)` indexes are unique among active rows. Row-result Person/Property/Opportunity identifiers are scalar history references, so the import service must check workspace ownership; the batch-to-group and row-to-batch links are relations. Migration state and physical constraints still require local database verification.
| Activities | [`TaskWorkspaceEntity`](../packages/twenty-server/src/modules/task/standard-objects/task.workspace-entity.ts) and [`TaskTargetWorkspaceEntity`](../packages/twenty-server/src/modules/task/standard-objects/task-target.workspace-entity.ts); [`NoteWorkspaceEntity`](../packages/twenty-server/src/modules/note/standard-objects/note.workspace-entity.ts) and note targets attach work to records. |

| AI | [`AgentEntity`](../packages/twenty-server/src/engine/metadata-modules/ai/ai-agent/entities/agent.entity.ts) is a core definition; [`agent-chat-thread`](../packages/twenty-server/src/engine/metadata-modules/ai/ai-history/standard-objects/agent-chat-thread.workspace-entity.ts), [`agent-message`](../packages/twenty-server/src/engine/metadata-modules/ai/ai-history/standard-objects/agent-message.workspace-entity.ts), message part and turn workspace entities persist conversations. |
| Communication | Message/thread/participant entities under [`messaging/common/standard-objects`](../packages/twenty-server/src/modules/messaging/common/standard-objects/); calendar event/participant entities under [`calendar/common/standard-objects`](../packages/twenty-server/src/modules/calendar/common/standard-objects/); campaign/list/delivery/suppression entities under [`emailing/standard-objects`](../packages/twenty-server/src/modules/emailing/standard-objects/). |

## Schema change paths

- Core entity changes require a generated fast or slow instance command. Historical TypeORM migrations under [`legacy-typeorm-migrations-do-not-add`](../packages/twenty-server/src/database/typeorm/core/legacy-typeorm-migrations-do-not-add/) are frozen. [`run-instance-commands.command.ts`](../packages/twenty-server/src/database/commands/run-instance-commands.command.ts) is the runner. Follow [`UPGRADE_COMMANDS.md`](../packages/twenty-server/docs/UPGRADE_COMMANDS.md), including version folder, timestamp, `up`/`down` and slow backfill rules.
- Workspace object/field changes flow through metadata and [`WorkspaceMigrationRunnerService.run`](../packages/twenty-server/src/engine/workspace-manager/workspace-migration/workspace-migration-runner/services/workspace-migration-runner.service.ts), which uses a transaction and invalidates caches. The [`syncable-entity-*` skills](../.claude/skills/) cover its specialized migration machinery.
- Data access should carry workspace/auth context through existing repositories/query runners. Permission bypass is for controlled internal paths only; inspect the caller and test cross-workspace access when modifying it.
